Privacy Policy

Last updated: 25 November 2026 · Oldo (com.oldo.app)

This privacy policy describes how the Oldo Android app (com.oldo.app) handles information. Oldo is an independent project. This page is a product disclosure based on how the app works today — it is not legal advice.

1. Who this covers

Oldo is a mobile app where people sign in, post short “moods,” browse others, send interest, chat after a match, and optionally place a short voice call when someone marks I’m free. The public experience is pseudonymous: other users see a generated pseudonym, not your Google name, email, or profile photo.

2. Information we collect

  • Google account identifiers. When you sign in with Google, our servers verify your Google ID token and store the provider subject id needed to recognize your account. We may store email if Google provides it for account operations; it is not shown to other users in the app.
  • Age. You confirm you are 18+. Separately, you may set a write-once birth year and month used to compute age for matching preferences (who can see whose moods).
  • Moods. Niche choice and optional description text, expiry time, and age-preference range for that mood.
  • Chat. Message bodies and related conversation metadata when you match and chat with someone. System notices such as “Missed call” or “Call declined” may appear in the thread.
  • Voice calls. When voice is enabled and you use I’m free / Call, we store call session metadata (for example session id, participants, channel id, start/end times, status and end reason). We request microphone permission to send your voice during an active call. Oldo does not record or store call audio. Audio travels device ↔ our voice processor (Agora) ↔ the other person for the duration of the call only (in transit).
  • Safety actions. Blocks, reports, and related snapshots needed to handle abuse. An in-call report may reference a call session id; it does not include audio.
  • Device push token. On Android, an Expo push token (via Expo / Google FCM) so we can send notifications while the app is backgrounded or closed.
  • App / session tech data. Session tokens (access + refresh). The refresh token is stored in Android SecureStore on your device so you can stay signed in after kill/relaunch. We also receive standard request metadata needed to run the API (for example approximate client IP for rate limiting).
  • App version header. The app sends a minimum app version header so outdated clients can be rejected.

3. How we use information

  • Create and secure your account and sessions.
  • Show feeds, interests, matches, and chat.
  • Run optional voice calls between matched users (place, ring, accept, decline, end) and keep the call working while both stay in the app.
  • Apply age preferences and safety tools (block / report / suspend).
  • Generate embeddings for mood text so “For you” / similarity features can work (see below).
  • Send push notifications with generic titles only (for example “New message”, “New request”, “New match”) — not the message or mood body. Ringing for voice currently relies on the app being open / polling while you are marked free — not a separate “incoming call” push.
  • Rate-limit abuse and keep the service reliable.

4. Sharing with service providers

We do not sell your personal information. We use processors needed to run Oldo:

  • Google — Sign-In identity verification; Android push delivery involves Google Play services / FCM as used by Expo.
  • OpenAI — Mood description (and related niche label text used for embedding) is sent to OpenAI’s embeddings API (text-embedding-3-small) so we can store a vector for matching features. See OpenAI’s privacy policy.
  • Agora — Real-time voice for matched calls. Call audio is transmitted through Agora’s network between your devices; Oldo’s API does not proxy or store that audio. Agora receives what is needed to join a channel (for example App ID, channel name, and a short-lived token our servers mint). See Agora’s privacy policy.
  • Expo — Expo Push API delivers notifications using your device token.
  • Hosting providers — Application API, database, and worker currently run on Railway when deployed; this website is served via GitHub Pages for oldo.social (DNS may use Hostinger).

Other users in a match can see your pseudonym, moods you share on the feed, chat messages you send them, and hear your voice during a call they join with you.

5. Retention and deletion

  • You can sign out without deleting your account (session cleared on device; account remains).
  • You can delete your account in the app: Settings → Delete account. That soft-deletes the account, scrubs mood text and your message bodies, removes push tokens, revokes refresh sessions, ends any ringing or active calls involving you, and unlinks Google identity so the same Google account can create a new Oldo user later.
  • Call session rows (ids, timestamps, status/end reason — not audio) may remain after deletion for integrity and safety correlation.
  • Reports may be kept for up to 90 days for safety after deletion, then pruned.
  • Inactive push tokens may be pruned after prolonged non-use (on the order of 60 days for unseen tokens).

Web instructions: Delete your Oldo account.

6. Security

We use HTTPS for the production API, authenticated requests for account data, and on-device SecureStore for the refresh token. Voice credentials (tokens) are short-lived and minted only for an active call. No method of transmission or storage is 100% secure.

7. Children

Oldo is for people 18 and older only. We do not knowingly create accounts for children.

8. Changes

If how Oldo handles data changes in a material way, we will update this page. Continued use after an update means you should re-read this policy when prompted by the app (for example when accepting terms at sign-in).

9. Contact

Oldo is an independent project and does not currently publish a support email on this site. Account and data deletion is handled in-app as described on the delete account page.
